# Benchmarks

Generated by `python -m scripts.benchmark --write` on 2026-10-24 (Python 3.13.3, Darwin arm64). Timings vary by machine; memory figures are deterministic for a given Python version.

Network: **125 stations, 127 segments** (service date 2026-10-26). Route-level graph: 155 nodes, 202 edges.

**Baseline** = the original HW4 implementation (`scripts/baseline_matrix.py`, ported from `legacy/`): two dense V×V matrices and O(V²) Dijkstra.

## 1. Graph memory

Memory retained by each graph structure after construction, measured with `tracemalloc`.

| Structure | Memory | vs. baseline |
|---|---|---|
| Baseline: adjacency matrix + edge-index matrix | 264.5 KB | n/a |
| Adjacency list (same information) | 27.9 KB | 89.5% less |
| `TransitGraph` (route-level nodes, transfer edges, lookups) | 100.1 KB | 62.2% less |

## 2. Shortest-path queries (all station pairs)

Every one of the **7,750 station pairs**, one point-to-point query each.

| Implementation | Total | Per query | Speed-up |
|---|---|---|---|
| Baseline O(V²) Dijkstra | 3.65 s | 471 µs | 1.0× |
| Heap Dijkstra O(E log V), same model | 0.42 s | 54 µs | 8.7× |
| Heap Dijkstra with transfer penalties | 0.40 s | 52 µs | 9.1× |
| All-pairs table (one single-source run per station) | 0.014 s | n/a | n/a |

Correctness: with the transfer penalty set to 0, the heap implementation matches the baseline on **7,750 of 7,750** pairs.

## 3. Route cache

20,000 queries drawn from a Zipf distribution (exponent 1.1) over all station pairs, so a few popular trips dominate, as in real usage. 4,092 distinct (origin, destination) queries.

| | Total | Per query |
|---|---|---|
| No cache | 1.087 s | 54 µs |
| LRU cache (2,048 routes) | 0.370 s | 19 µs |

Hit rate **76.9%**, 2.9× faster. The cache trades memory for speed: when full it holds 886.0 KB. It is cleared whenever live closures change the graph.

## 4. Scaling (synthetic networks)

Random connected subway-like networks; 30 random queries per size.

| Stations | Segments | Matrix memory | Adjacency-list memory | Memory saved | Matrix query | Heap query | Speed-up |
|---|---|---|---|---|---|---|---|
| 125 | 130 | 264.5 KB | 84.9 KB | 67.9% | 0.47 ms | 0.038 ms | 13× |
| 500 | 524 | 3.9 MB | 344.4 KB | 91.4% | 7.18 ms | 0.136 ms | 53× |
| 1,000 | 1,049 | 15.5 MB | 695.8 KB | 95.6% | 28.13 ms | 0.263 ms | 107× |
| 2,000 | 2,099 | 61.4 MB | 1.4 MB | 97.8% | 113.94 ms | 0.536 ms | 213× |

Matrix memory grows with V² while the adjacency list grows with V + E, so the gap widens as the network grows.
